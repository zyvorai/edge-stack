How they fit

Yard never replaces Nodra, Fleet or OTA. It pulls what those planes already own and shows it as assets, observations and integration status.

PathWhat suite CI proves
A · Device Agent to YardBearer gate, inventory and sensors pull, ingest 202
B · Nodra to YardDevices and twins join, OTA campaign list, numeric observations ingest
C · Fleet to YardSites, rollouts and OTA devices into the lifecycle summary shape
D · relay-pubsubDocumented backends, including the honest grpc scaffold

Who owns OTA

The OTA agent owns signed RAUC install and power-loss recovery. Fleet owns the device assignment and event ACK contract. Nodra owns twin-desired OTA and multi-site canary campaigns. Yard only displays them.

Who owns events

relay-edge stamps site-aware events and publishes through relay-pubsub or direct. relay-pubsub backends: memory, http, relay-events (production) and grpc (a scaffold).

Suite CI, and what it does not claim

The suite-ci workflow runs the smoke on every push and pull request to main. In-process stubs for Device Agent, Nodra, Fleet and a Yard ingest sink speak the same HTTP shapes Yard's connectors call (scripts/suite_peers.py, scripts/suite_smoke.py).

A green check means

Connector-facing URLs and auth headers still match what Yard expects. Nodra campaign list and Fleet rollout summary shapes still parse. Yard ingest still accepts the normalized inventory and observation bodies.

It does not claim

Full binary builds of every product, RAUC flashing or silicon hardware-in-the-loop, multi-writer Fleet HA, or live lab hosts. This job is hermetic. Product maturity lives in each upstream repo.

Quickstart

Needs Python 3 (standard library only) and make.

make ci
./scripts/run-suite-smoke.sh

make ci runs the four connector-path smokes and checks that the suite docs are present. Read more: docs/SUITE_CI.md.
